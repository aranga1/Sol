## Feature 1 — `sol chat`: Terminal Chat with Daemon LLM

### Problem
No way to query Sol's LLM from the terminal. Only the iOS app can talk to the agent.

### Design

**Command:** `sol chat`

**Architecture:** Single function `cmd_chat()` added to `setup/sol_cli.py`. No new files. `rich` installed into `~/.sol/venv` (the venv the sol shim already uses).

**UI Layout:**
```
╭─────────────────────────────────────────╮
│  Sol  ·  chat session  ·  /exit to quit │
╰─────────────────────────────────────────╯

  You › what's in my notes about WWDC?

  Sol › [streaming tokens appear here, markdown rendered]

        Sources: notes/wwdc-2024.md · notes/apple-visions.md
────────────────────────────────────────────
  You › 
```

**Session history:** In-memory list of `{"role": "user"|"assistant", "content": "..."}` dicts. Passed as `history` array on every `/api/query` request. Ephemeral — cleared when process exits.

**Streaming:** SSE parsed with `urllib` (already in sol_cli.py). `rich.Live` updates a `Markdown` renderable token-by-token so the response builds in place. Sources shown below each response as dim text.

**Special commands:**
- `/exit` or Ctrl-D → quit
- `/clear` → reset history, reprint header

**Error handling:**
- Daemon not running → friendly `fail()` message + exit
- 503 (index not ready) → inline warning, prompt continues
- Timeout → inline warning, session continues

**New dependency:** `rich` — installed into `~/.sol/venv` via `cmd_update()` and documented in daemon `requirements.txt`.

**Tests** (`daemon/tests/test_chat.py` — uses mocked HTTP):
- Mock SSE stream, verify tokens are collected into assistant message
- Verify history array grows correctly across turns
- Verify `/clear` resets history to `[]`
- Verify graceful exit when daemon returns 503

## Feature 3 — iOS Feedback / GitHub Issue Reporter

### Problem
No way for users to report bugs or request features without leaving the app or needing technical knowledge. Should go directly to GitHub without any backend dependency.

### Design

**Entry point:** New "Feedback" button in `DrawerView` footer, between "Open in Obsidian" and "Settings":
```
Open in Obsidian      (book.closed)
Feedback              (bubble.left.and.exclamationmark.bubble)
Settings              (gearshape)
```

**New callback** on `DrawerView`: `onOpenFeedback: () -> Void` — same pattern as existing callbacks.

**New file:** `ios/Sol/Views/FeedbackView.swift`

**Sheet contents:**
- Segment picker: Bug Report / Feature Request
- Title text field
- Description multiline text editor (`TextEditor`)
- Photo strip: up to 3 images from photo library or camera (same `UploadItem`/thumbnail-strip pattern as `NoteComposerView`)
- Submit button with spinner

**Image upload flow:**
1. Each selected image uploaded via `PUT /repos/aranga1/Sol/contents/feedback/attachments/{uuid}.png` (GitHub Contents API, base64-encoded body)
2. Response contains `content.download_url` — the raw GitHub URL
3. Issue body embeds each image as `![screenshot](raw_url)`

**Issue creation:** `POST https://api.github.com/repos/aranga1/Sol/issues`
- `Authorization: Bearer {BuildSecrets.githubIssuesPAT}`
- Title: `[iOS Bug] {title}` or `[iOS Feature] {title}`
- Labels: `["bug", "ios"]` or `["enhancement", "ios"]`
- Body: description + image markdown

**Build secret injection:**
- `ios/Sol/BuildSecrets.swift` — gitignored, generated by CI
- `ios/Sol/BuildSecrets.swift.template` — checked in, placeholder values
- CI step runs before `xcodebuild`: writes real PAT from `GH_ISSUES_PAT` secret

**Design language:** Follows Sol's warm neutral palette (DS tokens). Segment picker uses terracotta for selected state. Submit button uses `DS.terracottaGradient`. Error states inline, not modal alerts.

**Tests** (`FeedbackViewTests` — mock URLSession via protocol injection):
- Verify image upload fires before issue creation
- Verify issue body contains `![screenshot](url)` for each image
- Verify correct label array per segment selection
- Verify title prefix matches segment

## Feature 4 — iOS Vault Directory Picker in NoteComposerView

### Problem
All notes land in `Notes/` regardless of content. No way to organise notes into a folder structure from iOS. Obsidian's vault structure goes unused.

### Design

**Daemon changes:**

1. `NoteRequest` gains `folder: Optional[str] = "Notes"` field
2. `daemon/routes/notes.py` passes `folder` to `obsidian.create_note(filename, content, folder=body.folder)`
3. `obsidian_client.create_note` signature: `async def create_note(self, filename: str, content: str, folder: str = "Notes") -> str` — uses `/vault/{folder}/{filename}`
4. New endpoint: `GET /api/vault/directories`
   - Calls Obsidian `GET /vault/` to get file list
   - Extracts unique parent directory paths (excluding vault root)
   - Returns `{"directories": ["ideas", "ideas/ai", "reminders", ...]}` sorted

**iOS changes:**

`NoteComposerView` gets a `folderSection` view — placed directly below `tagSection`, same collapsible panel pattern:

**Folder picker UI (Sol design language):**
- Collapsed state: folder icon (`folder`) + selected path as terracotta chip, or `"Add to folder…"` in dim ink if none selected
- Expanded state: text field for search/create + scrollable suggestion list below
- Suggestion list: fetched directories from `GET /api/vault/directories` + recently used paths from `UserDefaults`, merged and deduplicated
- Each suggestion row: `folder` icon + path string + checkmark if selected
- Nested paths shown with indent or `/` separator for clarity
- "Create `{typed}`" row appears when typed text doesn't match any existing path
- Tapping a suggestion or "Create" sets the selected folder and collapses the panel
- ✕ on the chip clears selection (note goes to default `Notes/`)

**Persistence:** `UserDefaults` key `"sol.recentFolders"` — array of up to 10 recently used paths, prepended on each save.

**Visual design notes:**
- Follows identical structure to the tag section: same border, same background, same chevron animation on expand
- Folder chip uses the same pill style as tag chips but with a `folder` SF Symbol prefix
- Input field placeholder: `"Search or type a path…"` (matches tag field)
- Terracotta accent for selected state, `DS.inkFaint` for unselected/placeholder
- Smooth `.easeOut(duration: 0.15)` expand/collapse animation matching tags

**Tests:**
- `GET /api/vault/directories` — mock Obsidian response with nested file list, verify correct directory extraction
- Note creation with `folder="ideas/ai"` — verify Obsidian client called with `/vault/ideas/ai/{filename}`
- iOS: `UserDefaults` recent folders updated on save
- Default folder (`Notes`) used when no folder selected

## Implementation Order

Items are independent. Suggested build order:
1. Feature 1 (`sol chat`) — pure Python, fastest to ship, validates daemon streaming end-to-end
2. Feature 3 (Feedback sheet) — self-contained iOS + CI secret wiring
3. Feature 4 (Vault directory picker) — touches daemon + iOS + Obsidian client, most surface area

Each gets its own GitHub issue + feature branch + PR against `main`.

## TDD Approach

- Write failing tests first for each unit
- Green before moving to next unit
- All existing tests must continue to pass
- CI (`ci.yml`) must pass before PR merge
- TestFlight push on merge to `main`
